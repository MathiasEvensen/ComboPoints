# Combo Points

World of Warcraft **Midnight (12.0)** addon for:

- Feral Druids in Cat Form (optionally any druid spec in Cat Form) and all Rogues: Combo Points
- Paladins: Holy Power
- Windwalker Monks: Chi
- Warlocks: Soul Shards
- Arcane Mages: Arcane Charges

## Use

- `/cop` or `/combopoints` — open/close live configuration panel.
- `/cop unlock` — unlock tracker, then drag it.
- `/cop lock` — lock tracker position.
- `/cop resetpos` — reset only tracker position and detach it from a frame.
- `/cop resetconfigpos` — reset only the settings window's screen position and size.
- `/cop reset` — reset all defaults (asks for confirmation, then reloads the UI).
- `/cop toggle`, `/cop on`, `/cop off` — enable/disable tracker (also a checkbox in Layout tab, default on).

Settings are stored per character. In the **Profiles** tab, select a saved character from the scrolling dropdown, then use **Copy selected profile** to duplicate its complete profile, including frame attachment and position. Selection is temporary and clears when editor closes without copying. The same tab exports the current profile as text and imports a pasted one. Copy, Import, **Reset all defaults**, and `/cop reset` overwrite the profile and reload the UI, so each asks for confirmation first through `ns.Confirm`. Every other reset asks too: both **Reset position** buttons, `/cop resetpos`, and `/cop resetconfigpos`. Any new reset or overwrite action must go through `ns.Confirm`. New installs use Næpskrell's visual defaults. Settings use compact **Layout**, **Colors**, **Style**, and **Attach** tabs. A transparent live preview remains visible while editing Layout, Colors, and Style, showing full, 2-of-max, and empty states at the character's real point count with current shape, dimensions, spacing, colors, backgrounds, and borders. Drag the lower-right resize grip to resize the settings window; its controls stretch with the width, and the size is saved with the position. In Layout, **Only show usable specs** (on by default) limits the tracker to the specs listed above, and for Feral only while in Cat Form. Druids also get **Show in Cat Form for all specs** (off by default), which extends that to Cat Form on every other druid spec (Balance, Guardian, Restoration, and the pre-spec starting spec); it is disabled while **Only show usable specs** is off, since every spec and form then shows the tracker anyway. **Strata** (`-`/`+` buttons, default Medium) moves the tracker down or up through the UI layers in `ns.STRATA_LEVELS` (Background, Low, Medium, High, Dialog) for when it is drawn behind or in front of other frames. **Only show in combat** is off by default, leaving tracker visible at all times; enable it to hide tracker outside combat. Choose **Color mode: One static color** to use one active color for all points, or **Color mode: Individual** to configure each active point. The Colors tab shows one button per point the character really has, and the preview draws that many points: both read `ns.GetMaxPoints()`, which is the game's own `UnitPowerMax` for the tracked resource (4 for an Arcane Mage, 5 for most, 6 or 7 for a rogue with Deeper Stratagem / Secret Stratagem), so talents are never inspected directly, and both refresh when the maximum changes. Seven colors are stored; a point beyond them reuses the last one. Default individual palette: points 1–2 red, 3 yellow, 4–7 green. Toggle per-point box backgrounds and borders independently, then choose their colors. **Border thickness** (`borderSize`) counts screen pixels, not UI units, so each slider step is exactly one pixel at any UI scale. In **Style**, toggle the **Counter** to draw the active point total over the bar, capped at the spec's maximum; **Counter format** switches between `current` and `current/max`, **Hide counter at 0** (off by default) hides it while no points are active, **Outline counter** (on by default) toggles the counter's outline, and counter color, font, font size, and X/Y offsets are configurable. The font dropdown scrolls and previews each row in its own font, listing the fonts this client actually ships (each candidate is probed with a throwaway font string, since locale builds ship different subsets; only fonts that passed are remembered, and a font that failed is probed again on the next call, because the first probe at login can fail before the client has loaded the file) plus any font another addon has registered with LibSharedMedia-3.0; the library is used only when already loaded, never embedded. The counter stays centred on the visible points (the tracker frame itself is always sized for the full 10-point pool, so `ns.GetCounterCenterOffset` corrects for the unused slots) and follows the bar as size, spacing, and position change. In **Attach**, click **Pick frame**, hover any named UI frame, and press `Enter` to attach; `Esc` cancels. Picking can't start in combat, and entering combat or closing the settings window cancels it, since `SetPropagateKeyboardInput` is blocked during combat lockdown. The picker ignores the tracker, the settings window, and everything inside them, and checks `IsForbidden()` before any other method on a hovered frame. If the attached frame does not exist yet at login (another addon creates it later), the tracker waits on screen with `ns.attachmentPending` set and re-attaches on the next `ADDON_LOADED` or `PLAYER_ENTERING_WORLD`, or through a once-a-second lookup that `ns.ApplyLayout` runs for 60 seconds while the attachment is pending (for frames built by a timer or on first use); the saved frame name and offsets are never changed while waiting. An anchor WoW refuses falls back to the default position, and so does any position against the screen that leaves none of the visible points on screen, including a pending attachment's offsets (placement only, the saved value stays). After placing and sizing, `AlignToPixelGrid` nudges the tracker by a fraction of a pixel so its edges sit on whole pixels even with a centred anchor and an odd size; this too leaves the saved position alone. Choose one of nine attach points (for example `Top left` or `Center`) to align tracker and frame at that same point. A newly selected frame always starts with X/Y offsets reset to `0`; then drag the sliders (±500, kept narrow so dragging stays precise), click `-`/`+` to move 1 unit, or type an exact offset and press `Enter`; typed values and the buttons accept anything on screen, and the controls follow the tracker when it is dragged. When detached to screen, normal unlock-and-drag positioning remains available. WoW **Settings → AddOns → Combo Points** also includes the `/cop` and `/combopoints` access reminder, and the minimap addon menu (addon compartment) opens the settings window. `Esc` closes the settings window through its own `OnKeyDown`, not `UISpecialFrames`: WoW closes all of those frames together, which closed it whenever the game's Settings window closed. `Esc` is left alone and the Combo Points window stays open whenever `EscapeBelongsElsewhere` says so: in combat (the key can't be swallowed there, so closing would also open the game menu), while the game's Settings window, the game menu, a static popup, or the color picker is open, and while a spell is being cast or targeted. An open dropdown list (`Widgets.CloseOpenDropdown`) takes `Esc` before the window does. `ns.ResetPosition` and `ns.SavePosition` refresh every position control through `configPanel.RefreshPositionControls`; callers must not refresh them by hand. All style changes update tracker live. Configuration is saved automatically by WoW in its account `WTF/.../SavedVariables/ComboPoints.lua` file.

## Development install

`Interface/AddOns/ComboPoints` is a symlink to this repository's root directory. Edit files here, then use `/reload` in WoW (or restart client) for Lua/TOC changes. WoW does not hot-reload changed Lua files while running; live panel settings do apply immediately.

## Project layout

```text
ComboPoints.toc     # Midnight interface metadata, saved variable declaration, and Lua load order
Core.lua            # namespace setup, defaults, addon frame, table utils
CharacterState.lua  # per-character profile persistence, class/spec/power detection
Tracker.lua         # point frames, layout, live power updates
Widgets.lua         # reusable slider/label/color-picker/dropdown builders for the config UI
ConfigPanel.lua     # settings window: tabs (Layout/Colors/Style/Attach/Profiles) and live preview
SettingsCategory.lua # WoW Settings → AddOns panel entry
Bindings.lua        # slash commands and event wiring
.pkgmeta            # packager config (manual changelog, ignore list for files kept out of the release zip)
CHANGELOG.md        # release notes, edit before tagging a release
```

The repo root is the addon root — `BigWigsMods/packager` (see `.github/workflows/release.yml`) and CurseForge's own auto-packaging both require the `.toc` at the git checkout root, which is the standard layout for single-addon WoW repos.

## Release contents

The release zip (GitHub release and CurseForge upload, both built by the packager from the git checkout) must contain only what the addon needs to run: `ComboPoints.toc`, the Lua files it lists, the textures referenced from the TOC or code (`icon.tga`, `cop.tga`), plus `LICENSE` (MIT requires the notice to ship with copies) and `CHANGELOG.md` (the packager's manual changelog). Everything else stays out. Whenever you create or add a file, decide where it belongs:

- **Needed in game** — list it in `ComboPoints.toc` or reference it from code, and add it to the list above.
- **Committed but not needed in game** (dev docs like `CLAUDE.md` and `README.md`, tooling, test helpers) — add it to the `ignore:` list in `.pkgmeta`. Committed files ship unless `.pkgmeta` ignores them. Files and folders starting with a dot (`.github/`, `.gitignore`, `.pkgmeta`) are always ignored by the packager, so they need no entry.
- **Local only** (notes, research output, scratch files, editor and tool folders such as `NOTES.md`, `.remember/`, `research_notes/`, `reports/`) — add it to `.gitignore` before it can be committed. This includes output you generate yourself, such as research reports.

Before tagging a release, check `git ls-files` against this: every tracked file must be either needed in game or ignored in `.pkgmeta`.

The Lua files share state through a single addon-scoped table: each file starts with `local ADDON_NAME, ns = ...`, since WoW's loader passes the same `(name, table)` pair to every file of an addon. Mutable state (`ns.db`, `ns.tracker`, `ns.configPanel`, `ns.pointFrames`) and cross-file functions (`ns.ApplyLayout`, `ns.UpdateTracker`, etc.) live on `ns`. Because `ns.db` is a field access (not a per-function upvalue), every closure reads it live, so a reassignment like `ns.ResetCurrentProfile()`'s `ns.db = {}` is visible everywhere immediately — code should read `ns.db` (or `ns.db.<field>`) directly inside closures rather than caching a `local db = ns.db` that then gets baked into the closure. `ns.UpdateConfigPreview` defaults to a no-op in `Core.lua` until `ConfigPanel.lua` replaces it, so callers can invoke it unconditionally. Load order in `ComboPoints.toc` matters only for top-level execution — `Core.lua` before `CharacterState.lua` (needs `ns.DEFAULTS`), `Widgets.lua` before `ConfigPanel.lua` (needs `ns.Widgets`) — functions that read `ns.*` at call time work regardless of file order.

Profiles are never trusted as stored: every table that becomes `ns.db` (loaded from saved variables, copied from another character, or imported) goes through `ns.SanitizeProfile` in `CharacterState.lua`, which rebuilds it from `ns.DEFAULTS` — wrong types and unknown keys are dropped, numbers are clamped to the settings window's ranges. A new setting therefore needs a default in `ns.DEFAULTS` or it will not survive a reload, and a new numeric setting needs its range in `ns.NUMBER_LIMITS` (`Core.lua`), keyed by the setting's name; `Widgets.AddSlider` reads its range from that same table, so it takes no min/max arguments. `x`/`y` there are bounded at ±10000 only to reject garbage; never tighten that or otherwise rewrite `position` or `snapToFrame` on load, since a saved frame attachment and its offsets must survive every upgrade. Profiles are exported as JSON (`ns.SerializeProfile`). Import (`ns.DeserializeProfile`) tries `ParseJsonText`, then `ParseLegacyText` for the Lua-table text exported before 2.0.0; keep the legacy reader so old strings still import. Both are data-only parsers that never compile or run the pasted text; never use `loadstring` or any other code-loading call there. The nine anchor points live once in `ns.ANCHOR_POINTS` (`Core.lua`), shared by the Attach tab and validation.

Updates are driven by `UNIT_POWER_FREQUENT` filtered to the tracked resource's power token (second return of `ns.GetPowerType`) plus `UNIT_MAXPOWER` and `PLAYER_TALENT_UPDATE`. The event and tokens (`COMBO_POINTS`, `HOLY_POWER`, `CHI`, `SOUL_SHARDS`, `ARCANE_CHARGES`) match Blizzard's own class power bars in the 12.1.5 UI source. Combat state for **Only show in combat** is `ns.inCombat`, set from `PLAYER_REGEN_DISABLED`/`PLAYER_REGEN_ENABLED`; do not use `InCombatLockdown()` for it, since it is still false while `PLAYER_REGEN_DISABLED` handlers run. Everything drawn is pixel-snapped: `ns.GetPointMetrics`, `ns.GetBorderInset`, and `ns.SnapToPixels` round sizes to whole screen pixels for the frame's effective scale, and the tracker is placed with `PixelUtil.SetPoint`; without that, borders change thickness as the tracker moves. Use those helpers for any new size, and never the raw `ns.db` value. `UI_SCALE_CHANGED` and `DISPLAY_SIZE_CHANGED` re-run the layout. Lock/unlock always goes through `ns.SetTrackerUnlocked`, and border thickness through `ns.GetBorderInset`, so the tracker, preview, and settings window stay in sync. Dropdowns are the addon's own button plus scrolling list (`Widgets.AddScrollableDropdown`), not the deprecated `UIDropDownMenuTemplate`.

`## Version` in `ComboPoints.toc` is the packager token `@project-version@`, filled from the git tag at release, so the version is never edited by hand; the development install shows the raw token in the addon list.

Uses current namespaced APIs where available: `C_SpecializationInfo`, `C_UI`, and `Enum.PowerType`. It avoids protected action-bar manipulation and creates only addon-owned UI frames.
